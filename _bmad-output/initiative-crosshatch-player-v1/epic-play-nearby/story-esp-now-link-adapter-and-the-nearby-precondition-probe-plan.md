## Intent

**Problem:** Play Nearby has a link interface (`GameCore::ILink`, entry 2) and nothing that carries it over the air, and nobody knows what linking ESP-NOW costs in flash and internal RAM, the epic's largest unknown against 9,056 B / 160 B of share left. The lobby also needs a decision, not a screen, for "Wi-Fi is up or internal heap is under 100 KB".

**Approach:** Add `src/games/EspNowLink.{h,cpp}` (an `ILink` over ESP-NOW v2, channel 1, no encryption, brought up in AD-18's order, with its logic in a template over a driver so the host can inject a failure at each bring-up step), `src/games/FrameRing.h` (the radio-free receive ring), and `src/games/NearbyProbe.{h,cpp}` (a pure header-only decision plus a device reader); test them in new harness files; then measure the driver's own flash and static-RAM cost like for like and stop for the owner if it is over half the share.

## Boundaries & Constraints

**Always:** The receive callback only copies a frame into the ring and calls no `GameCore` code, takes no lock, allocates nothing, logs nothing. The ring and the peer table are one PSRAM block allocated at bring-up through `HalMemory::allocatePsram` (never static, never internal heap), null-checked before the radio is touched. Handle values are unique across link instances in the process: an instance tag in the high bits plus the peer slot (`ILink.h`, the epic Notes' "Assumption (orchestrator, 2026-10-12)"). `end()` is idempotent and leaves the radio off. No `GameCore` change: `ILink` and `Protocol` are the contract. `static_assert(GameCore::Protocol::MAX_FRAME_BYTES <= ESP_NOW_MAX_DATA_LEN_V2)` is in `EspNowLink.cpp`. Code adapted from crossplay carries `// Adapted from crossplay 0a1d17f src/apps_local/link/LinkRadio.cpp (MIT).` and its copyright line (as `test/game_core/FakeLink.h` does). Both `.cpp` files are whole-file `#if FREEINK_CAP_GAMES && !defined(SIMULATOR)` and are excluded from the shared host harness by name. `AGENTS.md` rules: `makeUniqueNoThrow` / `new (std::nothrow)`, locals under 256 B, `LOG_*` only, no static initializer (`constinit`/`constexpr` statics only, none mutable over 64 B), nothing hand-edited that is generated.

**Never:** No file outside `touches`. Not `platformio.ini`, no `sdkconfig` setting (if the 50 ms wake window needs `CONFIG_ESP_WIFI_STA_DISCONNECTED_PM_ENABLE` and the build lacks it, HALT as blocked), not `lib/GameCore/**`, `src/activities/**`, `freeink-sdk`, an upstream file, or `games/**`. No `NearbySession`, lobby, or `GameLink` task wiring (entries 8, 10, 11); nothing calls `EspNowLink` from the shipped firmware. No MAC address, channel, or peer-table fact in `GameCore`. No fallback to internal heap for the ring (if a Wi-Fi-task write to PSRAM proves unsafe, HALT for the owner). No `Serial.print*`. Do not commit the scratch measurement file.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Ring push/pop | frames 1 to 1,470 B pushed, then popped | whole frames, in order, with the sender's 6 B MAC; push copies and returns | none |
| Ring full | push into a ring holding `depth` frames | push returns false, `droppedFull()` +1, stored frames intact, never blocks | counted |
| Ring bad frame | push of length 0, over `maxFrame`, or null | false, `rejected()` +1, nothing stored | counted |
| Pop with a small buffer | next frame longer than the caller's buffer | that frame dropped (never truncated), `skippedTooLong()` +1, pop goes on to the next | counted |
| Probe | Wi-Fi off/on x heap 102,399 B / 102,400 B | `wifiInUse` is the reading; `lowMemory` is true only below 102,400 B; both flags reported, no priority picked | none |

## Implementation Notes

- Implemented by a context-free subagent from this plan; the host suite (2,169 tests, `EspNowLinkHarnessTest` among them) and the fast checks passed there and again in this session after the fix below. Firmware builds, `pio check`, `sim.sh build`, and the measurement had not run when this was written (see Verification).
- Deviation from Design Notes 4, kept: the `FrameRing` object itself is placement-new'd at the start of the PSRAM block (then its slots, then the peer table), so that on the abandoned-storage path (`shutdownEspNow` false, a callback may still run) the callback's ring pointer stays valid: the link object is freed but the leaked PSRAM block is not. `EspNow::BLOCK_BYTES` is therefore `RING_CONTROL_BYTES` (`sizeof(FrameRing)` rounded to 16) plus 11,840 B of slots plus 96 B of table, not the 11,936 B Design Notes 4 estimated; a test pins the layout.
- Verify-step changes: (1) `FrameRing`'s three counters moved from `fetch_add` to a relaxed load and store (each has one writer), because the ring object sits in PSRAM and a native Xtensa read-modify-write (S32C1I) does not work on external RAM. The build turned out to cover that case itself: `CONFIG_STDATOMIC_S32C1I_SPIRAM_WORKAROUND=y` (`framework-arduinoespressif32-libs/esp32s3/sdkconfig:2966`) routes every atomic through ESP-IDF's locked emulation (`std::atomic<uint32_t>::is_always_lock_free` is false on this toolchain, so a `static_assert` I first added failed the x4pro build and was removed). So a `fetch_add` would have been correct and only slower; the load and store stays, with a comment saying so. (2) The first firmware build failed: `makeLabel`'s local `HEX` collided with Arduino.h's `#define HEX 16` (the host never sees the macro); renamed `HEX_DIGITS`. (3) `pio check -e x4pro` flagged the `#error` guard (cppcheck never sees the generated `sdkconfig.h`); an inline `cppcheck-suppress preprocessorErrorDirective` above it clears it, and `sticky` builds, so the option is set there too.
- Measurement method differs from Design Notes 8 in one detail: the first scratch reference (a `const void*` data object marked `used, retain`) was dropped by the linker (B equalled A, no `makeEspNowLink` symbol), so the scratch file instead holds a `__attribute__((constructor))` function that calls `makeEspNowLink()`, `receive`, `broadcast`, and `hostLabel` behind a `volatile int` that is never 1. It is deleted; `git status` shows no `ScratchEspNowRef.cpp`.
- The flash stop fired and is lifted. The driver cost +11,456 B of flash and +80 B static RAM (Verification, Results), over the 4,752 B half-share stop; the run halted `blocked`. The owner answered in the epic Notes, "Decision (owner, 2026-10-12, the flash budget, after entry 5's stop)" (option 1 of four): the driver cost is accepted and the entry continues as built; the gate rises to 290 KiB, this epic's share is now 29,984 B flash and 160 B static RAM over the base (+258,048 B / +784 B), and the half-share stop was lifted from `tickets.toml` entry 5's verify and R15. This pass resumed from `in-review` on that Decision, re-ran the review and the verification, and re-measured on the merged branch (Verification, Results, second pass). The two other owner stops still hold: a needed `platformio.ini` or sdkconfig change, and internal heap for the ring.

## Design Notes

Settled by: epic R7, R8, R15; the Notes' Decisions "owner, 2026-10-12, entry 2's plan checkpoint, the link contract", "Assumption (orchestrator, 2026-10-12, from entry 2's review)", "owner, 2026-10-12, confirmed on CarpeTelam/crosshatch-player#39" (the half-share stop), "Open (2026-10-12, entry 5)", "inception, 2026-10-11, `EspNowLink` is written against `esp_now.h`"; spine AD-2, AD-13, AD-18; `lib/GameCore/ILink.h`.

1. **`FrameRing`** (header-only, `<atomic>`, `<cstring>`, `<span>`; no allocation, no log). `slotBytes(maxFrame) = (2 + 6 + maxFrame + 3) & ~3` (u16 length, 6 B MAC, frame, padded to 4); `storageBytes(depth, maxFrame) = depth * slotBytes`. `bool attach(uint8_t* storage, size_t storageSize, size_t depth, size_t maxFrame)`: false unless `depth` is a power of two >= 2, `maxFrame` in 1..65,535, the storage is large enough; it resets the indices and counters. `void detach()`. Producer (the Wi-Fi task): `bool push(const uint8_t* mac, const uint8_t* data, size_t length)`: false (nothing counted) when not attached; false with `rejected_`++ for a null pointer, a zero length, or a length over `maxFrame`; false with `droppedFull_`++ when `tail - head >= depth`; otherwise copy MAC, length, bytes into slot `tail & (depth - 1)`, then `tail_.store(tail + 1, release)`. Consumer: `bool pop(uint8_t* mac, std::span<uint8_t> out, size_t& length)`: loop on `head != tail_.load(acquire)`; read the slot, copy only if `length <= out.size()` (else `skippedTooLong_`++ and go on); `head_.store(head + 1, release)` after the copy; return true on the first copy. `head_`/`tail_` are monotonic `std::atomic<uint32_t>`; counters are `std::atomic<uint32_t>` with relaxed order; accessors `droppedFull()`, `rejected()`, `skippedTooLong()`. Why a ring of fixed slots over caller memory: the producer is another task, the memory is PSRAM that `EspNowLinkT` owns, and the class stays testable. Depth 8 and `maxFrame` 1,470 (`EspNow::RING_DEPTH`) is 11,840 B of PSRAM; 8 outruns the `GameLink` task's drain at ADVERT and STATE rates and a full ring costs a resend, not state (R2, R5); it is an estimate until the device run.
2. **Probe.** `namespace NearbyProbe { inline constexpr size_t MIN_INTERNAL_HEAP_BYTES = 100 * 1024; struct Readings { bool wifiInUse; size_t freeInternalHeapBytes; }; struct Verdict { bool wifiInUse; bool lowMemory; constexpr bool canOpen() const { return !wifiInUse && !lowMemory; } }; constexpr Verdict decide(const Readings&); Readings read(); }`. `lowMemory = free < MIN` (102,399 B refuses, 102,400 B passes). The verdict carries both facts and picks no message: R8 gives one message for each cause and says nothing of both at once, so which one shows is entry 10's choice with this on hand (a low-heap reading usually follows Wi-Fi being up, so entry 10 will probably show Wi-Fi first; not decided here). `read()` in `NearbyProbe.cpp`: `{WiFi.getMode() != WIFI_MODE_NULL, HalMemory::getInternalHeap().freeBytes}`; entry 16 adds the simulator reader to the same file.
3. **Driver seam.** `EspNowLinkT<D>` takes a driver `D` satisfying `concept EspNowDriver`: `bool enterStation()` (persistent off, STA mode, auto-reconnect off, remembering the previous auto-reconnect), `bool leaveAccessPoint()` (disconnect, waited out up to 500 ms), `bool setChannel(uint8_t)`, `bool initEspNow()`, `bool registerReceive(FrameRing&)`, `bool addBroadcastPeer(uint8_t channel)`, `void enablePowerSave(uint16_t wakeWindowMs)`, `bool readMac(Mac&)`, `bool sendTo(const uint8_t* mac, std::span<const uint8_t>)` (registers the unicast peer on first use, then sends; false for any non-OK), `bool shutdownEspNow()` (unregister callback, `esp_now_deinit`, power save off, then wait out a callback still running; false if one still is), `void leaveStation()` (Wi-Fi off, previous auto-reconnect restored). `EspNowLinkT::bringUp()` sets `stationHeld_ = true` before the first call, runs the steps in this order (AD-18's amended order; the numbers are the steps): `enterStation`, `leaveAccessPoint`, `setChannel(1)`, `initEspNow` then `espNowUp_ = true` at once, `registerReceive`, `addBroadcastPeer`, `enablePowerSave(50)`, `readMac`; each fallible step on failure logs `LOG_ERR("LINK", ...)` and calls `end()`. `end()`: `started_ = false`; if `espNowUp_` then clear it and call `shutdownEspNow()` (false: `storageAbandoned_ = true`); if `stationHeld_` then clear it and call `leaveStation()`. The destructor calls `end()`; if the storage was abandoned it `release()`s the PSRAM block (a deliberate leak: a callback may still hold the ring; logged) instead of freeing it. What each guard protects: `stationHeld_` before the first call so a failed `WiFi.mode` still hands Wi-Fi back; `espNowUp_` at once after `esp_now_init` so a later failure does not leave ESP-NOW up and fail every later bring-up on `esp_now_init` (crossplay `LinkRadio.cpp` comments); auto-reconnect off before the disconnect and the disconnect waited out before the channel is set (a channel set while associated is silently reverted).
4. **Factory and allocation.** `makeEspNowLink()` allocates the link with `new (std::nothrow)` (a private constructor, so not `makeUniqueNoThrow`), then one PSRAM block of `FrameRing::storageBytes(8, 1470) + PeerTable::storageBytes(16)` = 11,936 B (a ring and a table that a different task writes and that live as long as the radio; stack and internal heap rejected: 11.9 KB, SPEC Constraints), null-checked with `LOG_ERR` (size) before any driver call, then `bringUp()`. The label is `makeLabel(model, mac)` = the model text, a space, and the MAC's last two bytes as 4 upper-case hex digits, the model cut so the whole is at most 16 B (`Protocol::MAX_HOST_LABEL_BYTES`); the model is "X4 Pro" under `FREEINK_DEVICE_X4PRO`, "Sticky" under `FREEINK_DEVICE_STICKY`, else "Reader". `hostLabel()` is on `EspNowLinkT`, not `ILink` (the Notes' Assumption). `ringOverflows()` and `unnamedPeerDrops()` give entry 8 its `LINK` figures.
5. **Handles and the peer table.** `PeerTable` over caller memory (`MAC_BYTES` per entry, capacity 16, never evicts, so a handle is never reused): handle value = `(instanceTag << 8) | (slot + 1)`, tag 24 bits from `inline constinit std::atomic<uint32_t> nextInstanceTag` (`fetch_add`, wrapping within 1..0xFFFFFF; a 4 B mutable static, AD-2-legal). `findOrAdd(mac)` returns `NO_PEER` when full (counted); `macOf(handle)` returns null for `NO_PEER`, another tag, or a slot not yet used. `receive` pops, names the sender (`findOrAdd`), drops the frame when it cannot name it, and never returns `NO_PEER`. Capacity 16 plus the broadcast peer is under ESP-NOW's 20.
6. **Real driver.** All calls mirror crossplay's `begin`/`end`/`send` (cited in a comment). The callback is `void onReceive(const esp_now_recv_info_t*, const uint8_t*, int)`: `inCallback.fetch_add(1)`; `FrameRing* ring = activeRing.load()`; if non-null and the arguments are valid, `ring->push(info->src_addr, data, len)`; `inCallback.fetch_sub(1)`. `activeRing` is a `constinit std::atomic<FrameRing*>` and `inCallback` a `constinit std::atomic<uint8_t>` (5 B of mutable static). `shutdownEspNow` stores null into `activeRing`, unregisters the callback, deinits, sets power save off, then waits (`vTaskDelay(1)`, at most 100 ms) for `inCallback == 0` and returns whether it got there: this closes the one race between the Wi-Fi task and the PSRAM block's release. Wake window: `esp_wifi_set_ps(WIFI_PS_MIN_MODEM)` then `esp_now_set_wake_window(50)`, failures logged, not fatal. The wake window works while disconnected only with `CONFIG_ESP_WIFI_STA_DISCONNECTED_PM_ENABLE` (`esp_now.h` documents it): the x4pro prebuilt Arduino libs set it (`framework-arduinoespressif32-libs/esp32s3/sdkconfig:2307`), and `EspNowLink.cpp` has `#ifndef CONFIG_ESP_WIFI_STA_DISCONNECTED_PM_ENABLE #error` so an env without it fails the build instead of silently losing the window (the owner's stop). `esp_now_send` copies the frame (`esp_now.h`: the buffer need not stay valid), which is `ILink`'s copy contract. A Wi-Fi-task callback writing PSRAM: IDF runs the callback in a normal task, which the cache-disable windows suspend; no ISR is involved. This is reasoning from the IDF documentation, not a device measurement; entry 11's smoke run is the check, and the plan records it so.
7. **Test doubles** (brief AI-4). `FakeRadio` (per node: call log, a "fail step k" setting, associated/channel/espNowUp state, MAC, the registered ring), `FakeDriver` (forwards to its `FakeRadio*`), `FakeAir` (the medium: a broadcast reaches every other node's ring through `FrameRing::push`, a unicast only the node with that MAC; same thread).
