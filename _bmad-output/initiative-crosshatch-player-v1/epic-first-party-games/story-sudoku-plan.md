## Intent

**Problem:** Epic 8 ships Sudoku as the solo game of R1, R4, R5, R8, and R9, and nothing in `games/` plays it: it needs Sudoku+'s interaction, a bank of public-domain puzzles each filed under the band a Lua port of crossplay's technique ladder needs, HINT, CHECK, FILL NOTES, a menu panel, a HOW TO PLAY page, and elapsed and best times, all inside API level 1, a 700 B snapshot, a 2 M-instruction call, and a 256 KB Lua heap.

**Approach:** Add `games/sudoku/` (the board module copied once from `games/ultimate-tic-tac-toe/`, a solver port, a generated `puzzles.lua`, the game, its note images) and its companion folder `test/game_script/first_party/sudoku/` (rounds, `checks.lua` with an independent solution counter, the bank tool and the note-image tool under `tools/`), built from the owner's answers to the checkpoint choices D1 to D6 in Design Notes; no engine, harness, script, or workflow file changes.

## Boundaries & Constraints

**Always:** API level 1 only; `games/sudoku/` is the whole package and names no repository path and shares no file or `require` with another game (R2); the board module is a byte-for-byte copy of `games/ultimate-tic-tac-toe/board.lua` (C3, R3), after which Sudoku owns it and no test ties the two together; every snapshot at every step of every round at most 700 B (R9); a move at most 256 B; no call passes 2,000,000 instructions, 2,048 frame commands, or the 256 KB Lua heap; user text is the game's own, not `tr()`; icons come from `GameIcons` (`pencil-simple`, `eraser`, `arrow-u-up-left`, `lightbulb`, `check`, others only from `api-level-1.txt`'s `icon` lines); `apply` is the only thing that changes `state`, `status` depends on `state` alone, and a rejection returns `nil, reason` with the reason at most 64 B; the band a puzzle is filed under is the hardest technique the shipped solver needs, and a source puzzle it cannot finish is left out; each puzzle's 12-character hash and the source commit are recorded in `puzzles.lua`; the credit text is exactly "Puzzles from the Sudoku Exchange puzzle bank (sudokuexchange.com), public domain." on the HOW TO PLAY page.

**Never:** any change under `src/`, `lib/`, `docs/crosshatch/api-level-1.txt`, `scripts/` (the bank tool is the game's, in `tools/`), `test/game_script/harness/`, `test/game_script/fixtures/`, `.github/workflows/`, `games/ultimate-tic-tac-toe/`, `games/battleship/`, the games check's files, `first_party/README.md`, or any upstream file; no on-device generation; no `nearby` or `pass` mode; no text entry; no clock drawn while solving; no `Serial` or `os`/`io` use; no test that compares Sudoku's `board.lua` with another game's; no edit to `deferred-work.md` or `tickets.toml`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Select | tap an empty cell or an own digit's cell | cell selected; the tap is `ui` only, so `ver` is unchanged | none |
| Deselect | tap the selected cell | nothing selected | none |
| Write | cell selected, pencil off, tap a pad digit | digit written, the cell's notes cleared, cell deselected, focus on that digit; one undo step | clue cell: no move, focus moves instead |
| Clear | tap the digit the selected own cell holds | cell cleared, deselected; one undo step | none |
| Note | pencil on, cell selected and empty, tap a digit no peer holds | that mark toggles, cell deselected; one undo step | filled cell, or a digit a peer holds: no move, selection kept |
| Focus | no cell or a clue selected, tap a pad digit | focus moves to the digit (clears if it was there) | none |
| ERASE | own cell selected | digit and notes cleared, cell stays selected; one undo step | a clue selected: `apply` rejects "Clues cannot be changed" and the message shows |
| UNDO | ring holds steps | one cell back, or one whole FILL NOTES | empty ring: `apply` rejects "Nothing to undo" |
| FILL NOTES | menu, an empty cell lacks a candidate | every legal candidate into every empty cell; one undo step; the panel closes | every cell already right: "Nothing to fill" |
| HINT, wrong digit | the player's grid has a digit that disagrees with the answer | that cell selected, "Wrong digit" named, never the right one; the hint flag set | none |
| HINT, correct so far | no wrong digit | the cell the ladder can prove next selected, its rule named, never the digit; hint flag set | none |
| CHECK | menu | strikes drawn through the player's wrong digits, or "All correct"; no flag; marks last until the next edit | none |
| Solve | last digit written, no clash | `status` is over with `winners = {1}`; end screen with the elapsed time and the best time for the band; on `over` `input` records the best time unless the hint flag is set | none |
| Clash | a digit repeats in a row, column, or box | both cells marked | none |
| Menu toggles | SHOW REMAINING, SHADE PEERS, notes as dots or digits | the row shows the new state; kept in `ch.store` per device | a store that cannot be read falls back to the defaults |
| Second deal | `setup` with another seed (or Play again) | a different grid; stale `ui` (selection, marks, timer start) is reset | none |

## Implementation Notes

### Part 1 (board, manifest, solver, note images, bank tool, `puzzles.lua`, `counter.lua`), for part 2 to build on

Done and verified by measurement as below; nothing committed. Part 2 owns `layout.lua`, `main.lua`, `taps.lua`, rounds, `checks.lua`, the Design Notes D2/D4 text, and every firmware-side step.

**`games/sudoku/solver.lua` (final interface).** A grid is a 81-character string, row by row, `"0"` or `"."` for an empty cell, `"1"`..`"9"` for a digit (any other character is read as empty, so a game's `state.v` must be mapped first: clues are `"1"`..`"9"` there, the player's `"a"`..`"i"` become `"1"`..`"9"` or `"0"`). Cells of the interface count from 1, units from 0 (rows 0..8, columns 9..17, boxes 18..26). Every function copes with any 81-character grid; a string of another length is "contradictory".
- `solver.grade(grid) -> band, rung`; band 1 Easy .. 4 Expert, rung 1..10 the hardest rung applied; `nil, rung` when the ladder cannot finish it (or `nil, 0` for a contradictory grid). A complete grid grades 1, 1.
- `solver.answer(grid) -> string | nil`: the solved grid (81 digits) when the ladder finishes it, else `nil`. Call it on the clues only.
- `solver.hint(grid) -> cell, digit, rung, unit`: the first placement the ladder proves (crossplay's `nextHint`: the lowest-numbered naked single, else the first hidden single by unit then digit, else push the cheapest elimination from rung 3 up and look again) and the hardest rung needed to reach it; `unit` is the unit of a hidden (only-cell) single, else `nil`. Returns `nil` when the grid is complete, contradictory, or the ladder is stuck. Call it on the clues plus the player's CORRECT digits only (a wrong digit makes the grid contradictory or, worse, merely misleads it; the game finds the wrong digit by comparing with `answer` first, as the Design Notes say).
- `solver.band_of(rung)`, `solver.name(rung)` (rung names for HINT: Only digit, Only cell, Locked candidates, Naked pair, Hidden pair, Naked triple, Hidden triple, X-wing, XY-wing, Swordfish; all at most 17 bytes), `solver.RUNGS` (10), `solver.BANDS` (4).
- The tables build on the first call (11,023 instructions) and are reused; a call allocates nothing. Heap: the solver's compiled code 32.6 KB and its tables 28.7 KB once built (measured with `collectgarbage("count")`, host Lua, so 61 KB); the counter 13.2 KB; `puzzles.lua` 39.6 KB resident; `board.lua` is the copy. The solver, counter, and bank together are 114 KB resident (measured), which leaves about 142 KB of the 256 KB cap for `main.lua`, `layout.lua`, the checks' entries, and the sandbox's own overhead (compiled code is 1.5 to 3.5 times its source); measure before adding a table.
- Instruction cost (host Lua 5.5.1 built from `lib/lua/src`, count hook of 1, tables already built), over the 400 bank puzzles, the largest per band Easy / Medium / Hard / Expert: `grade` (one full solve) 63,637 / 69,646 / 84,272 / 169,512; `answer` plus `hint` on the clues (the first HINT or CHECK) 115,089 / 113,152 / 130,719 / 213,950.
- Faithfulness: same band, same hardest rung, and the same hint (cell, digit, rung, unit) as crossplay's C++ ladder (`SudokuCore.cpp` at `74742d4e`, `solve(grid, Swordfish)`, `nextHint`) on all 893,916 records of `easy.txt`, `medium.txt`, `hard.txt`, and `diabolical.txt` (774,235 + 119,681; the 119,681 diabolical and 122,691 of `hard.txt` are not finished by either, and agree on that), 0 mismatches; and on 2,400 partially filled grids (the clues plus up to 45 random correct digits of 600 bank puzzles), 0 mismatches. The scratch comparer is under `scratchpad/8.3/ref/` (`ref.cpp`, `cmp.lua`), not in the repository. The two singles are run to a fixpoint from a queue (any order reaches the same position), and every rung from 3 up takes the first instance in crossplay's order; a rung skips units (digits, for the fish) whose candidates have not changed since it last found nothing there.

**`games/sudoku/puzzles.lua`.** `local puzzles = require("puzzles")` returns a table: `commit` (the bank commit, `d8c8ebaee0c08c412cfba96af1923dfa61c83317`), `per = 20` (records to a string), `width = 93` (characters in a record: `hash12 .. digits81`), `cap = 1000000`, `count = {100, 100, 100, 100}` (puzzles per band), `most = {...}` (the largest worst-call cost kept per band, instructions, table building included), `costly = {{i,...}, ...}` (per band 1..4 the indices of its four costliest puzzles, the costliest first), and `easy`, `medium`, `hard`, `expert` (each a list of five strings of 20 records). The accessor is `puzzles.get(band, i) -> hash12, digits81` (band 1..4, i from 1; digits are `"0"` for an empty cell). 40,192 bytes (under the 131,072 member limit); the header carries the source URL and commit, the credit line, the tool's settings, and the measurements below.

**`test/game_script/first_party/sudoku/counter.lua`.** `counter.count(grid) -> n, solution`: n is 0 (no solution, repeated digit in a unit, or not 81 cells), 1, or 2 (two or more); `solution` is the first one found as an 81-digit string, or `nil`. Independent of `games/sudoku/` (it requires nothing). Takes a forced move (a digit with one home in a unit) before the fewest-candidates cell. Cost on the 400 bank puzzles: at most 142,372 (Easy), 310,327 (Medium), 498,524 (Hard), 473,470 (Expert) instructions, so one call per puzzle fits a 2 M budget with room (the bank tool also drops a puzzle the counter needs more than `--count-cap`, 1,500,000, for, or does not find exactly one solution of; none was dropped). The first (fewest-candidates-cell-only) version of the counter needed 4,032,600 instructions on one finished puzzle of a 998 puzzle sample, which is why it takes forced moves now; a diabolical sample of 300 (never in the bank) still needed up to 1,182,600, so do not run it on a puzzle outside the bank in a check without budget for that.

**G, the game (R4, R5, R9).**
- `state = {l = level 1..4, v = 81 chars, n = 162 B, u = ring, z = notes copy (absent unless a fill is in the ring), t = elapsed ms, h = 1 when HINT was used (absent otherwise)}`. `v`: `"0"` empty, `"1"`..`"9"` a clue, `"a"`..`"i"` a player digit (1 to 9), so the clues are in the snapshot and a resume, HINT, CHECK, and a round's `steps(state)` need no bank. `n`: two bytes per cell, little endian, bit 0 = digit 1 (`string.pack`/`unpack`). `u`: a string of 3-byte records, the oldest first, at most R (D4) of them, the record being (cell, previous digit, previous notes), with one reserved cell value marking a FILL NOTES step. The bank is not needed after `setup`: `setup` requires `puzzles`, picks `ctx.settings.level`'s band, one record at random, and a random symmetry (digit relabelling, band and stack swaps, row swaps within a band, column swaps within a stack, transposition; each by `math.random`, which the runtime seeds), builds `v`, and returns; the symmetry is applied by a pure function in a game module so a check can test it alone.
- Moves, positional tables, every one ending in `dt`, the milliseconds since the previous move (an integer at least 0, which `apply` adds to `t`; a move is rejected when it is not): `{"w", cell, digit, dt}` write (the digit the cell holds clears it), `{"n", cell, digit, dt}` toggle a note, `{"e", cell, dt}` erase, `{"u", dt}` undo, `{"f", dt}` fill notes, `{"h", dt}` mark HINT used. `apply` validates every field (integer, in range) and rejects with: "Clues cannot be changed" (a clue cell, for `w`, `n`, `e`), "Nothing to undo", "Nothing to fill" (every empty cell already holds exactly its candidates), "That mark is not possible" (a note on a filled cell or for a digit a peer holds), "The grid is solved" (any move once `status` is over), "Bad move" (malformed). Every reason fits 64 B.
- `status`: `{over = true, winners = {1}}` when no `"0"` is left and no digit repeats in a row, column, or box; else `{turn = 1}`.
- `input`: `rejected` sets `ui.message`; `over` records the best time (`ch.store.get()` then `set`: a table with the toggles and `best` per level in ms; only when `state.h` is unset and `state.t` is lower than the stored one or none is stored) and caches it in `ui`; a `tap` goes by `ui.panel` (menu rows, help page closes on a tap, else grid, pad, rail) per the I/O matrix. A new puzzle is told from the last by the clue digits of `state.v` (a `ui.sig` the first draw or input after `setup` compares): when it differs `ui` is reset (selection, marks, panel, message) and the timer origin `ui.last` is set to `ch.time.ms()`, because Play again keeps `ui` (game-api-seed section 2) and `ch.time.ms()` counts from the game's start, and a resumed match starts a new VM; each move's `dt` is `ch.time.ms() - ui.last` and `ui.last` then moves to now, so the first move's `dt` counts from the round's first frame, and a sleep in between is excluded because the resumed VM's clock starts over and `ui` is empty. Any edit move (`w`, `n`, `e`, `u`, `f`) clears HINT's and CHECK's marks and the message before it is returned. HINT (menu row) runs the solver in `input` (answer, then hint), sets `ui.sel` and a message naming the rung (or "Wrong digit" when a digit disagrees with the answer, which outranks any deduction), and returns `{"h", dt}`; CHECK runs the answer and sets `ui.check` (a set of cells, or all correct) and returns no move (it changes nothing in `state`); FILL NOTES returns `{"f", dt}`. The answer is cached per clue string in a module upvalue. The toggles are read from `ch.store.get()` once per puzzle into `ui` and written back with `ch.store.set` when one changes.
- `draw`: seat 1 only; white clear; by `ui.panel` the menu panel (HINT with `lightbulb`, FILL NOTES, CHECK with `check`, SHOW REMAINING, SHADE PEERS, NOTES AS, HOW TO PLAY, CLOSE, replacing the board), the HOW TO PLAY page (rules, controls, the credit, wrapped with `ch.text_width`), or the board: header, `board.draw_grid`, per-cell ground (clue `dark`, SHADE PEERS `light` for the selected cell's row, column, and box, the focused digit's copies `black` with a white numeral), digits, notes (dots, or the 18 images drawn at the slot centre, grey for all but the focused digit, which draws black), clash and CHECK marks, the selection frame, the pad with SHOW REMAINING counts and the focus frame, the rail (`pencil-simple` inverted while on, `eraser`, `arrow-u-up-left`, MENU). A solved grid draws the end screen: "Solved", the elapsed time as `m:ss`, the best time for the band (or "no best time after a hint"). The worst frame (every empty cell with nine marks, SHADE PEERS on) must stay under 2,048 commands and the icon and image pixel limit; the checks draw it.
- The first frame after `setup`, a resume, or Play again requests a full refresh as other screens do not (`ch.gfx.refresh("full")`), and the menu panel and help page open and close with a full refresh (`sudokuplus.md`, The MENU panel).

**S, the solver.** Port the ladder rung for rung: naked single, hidden single, locked candidates (pointing and claiming), naked pair, hidden pair, naked triple, hidden triple, X-wing, XY-wing, swordfish; apply the cheapest rung that fires and restart; the hardest rung used is the grade (`levelOf` as crossplay: singles Easy, locked candidates Medium, pairs Hard, everything above Expert). The port measured above is naive (a table per unit, a pair loop per rung); the shipped one should cache unit position masks and peers where that cuts instructions, and must give the same band as the C++ ladder on every bank puzzle (the 1,200-record agreement above is the spot check; `checks.lua` proves each puzzle at its filed band). `hint` ports `nextHint`: push eliminations forward silently, report the first placement and the hardest rung needed to reach it, none when the grid is complete or broken. Tables are built on first use, not at load, so a game that never calls HINT does not hold them; the heap is measured by the games check.

**B, the bank tool and `puzzles.lua`.** `make_bank.py` takes the bank clone, the band size, the cap, and an optional host `lua`; it asserts `git rev-parse HEAD` of the clone against the commit it writes, drops records whose SHA-1 prefix is not their hash, merges `easy.txt`, `medium.txt`, and `hard.txt` in hash order (the bank's own order for randomising), grades candidates in batches through `grade.lua` (band, finished or not, cost) until every band holds its size, skips the unfinished and those over the cap, and writes `games/sudoku/puzzles.lua`: a comment header (repository URL, commit, size, cap, the shipped solver's file name), per band a table of strings of 10 or 20 fixed-width records (`hash12` then `digits81`; chunked strings, measured above, keep the load peak near the file size), and per band the indices of the costliest records. Deterministic: the same inputs give the same bytes. The `puzzles` module returns `{commit = "...", easy = {...}, medium = {...}, hard = {...}, expert = {...}, costly = {...}}`; a small accessor in the game reads record i of a band. Not run by CI.

**K, the companion folder.** `counter.lua` (independent of `solver.lua`: bitmask rows, columns, and boxes, fewest-candidates cell, returns 0, 1, or 2). `checks.lua` entries: per puzzle, a run that checks the record's shape (hash12 and 81 digits, no repeated digit among the givens in any unit), that `counter` finds exactly one solution, that `solver.grade` finishes it at the band it is filed under, and that the cost recorded is not exceeded (a fault if the call passes 2 M: a puzzle that does is dropped by the tool, so the check proves the tool's cap held); the costliest puzzle of each band run through `setup`'s symmetry, `input`'s HINT and CHECK, and `apply`'s FILL NOTES, each its own entry so a fault names it; the symmetry preserves validity and uniqueness on a sample; the second-`setup` check (two seeds, different grids; the same seed, the same grid); `apply` rejections (a clue, a malformed move, an out-of-range cell, a note on a filled cell, a negative `dt`); undo of a cell, of a fill (then on into the steps before the fill, per D4's answer), a second fill (drops the older fill and what precedes it), and ring wrap (the oldest step dropped; a fill step that is the oldest is dropped with its copy); the snapshot of a ring-full state with a fill in it at most 700 B; the toggles and best-time logic (a lower time replaces, a higher does not, a hint solve records none); a pure function that lists the cells with a clash (the clash row of the matrix, which no round can assert because the check sees text commands only); a `ch.store` that holds nothing or a table without the keys gives the defaults; layout checks (the pad's keys and the grid's cells are exact inverses of `key_at` and `cell_at` over every pixel, every target at least 44 px, the rail as tall as the pad). Heap: the checks VM carries the solver, the counter, the bank, and the entries, under the same 256 KB cap; build the entries compactly (a name and a function each, or one shared function over a cursor) and measure; if one entry per puzzle does not fit at the chosen D1 size, batch puzzles by the costs the tool recorded. `taps.lua` (module `taps`: the centre of a cell, a pad key, a rail control, a menu row, from `layout`; `taps.solve(state, opts)` returns the steps that write every missing digit of the answer from `solver.answer`, a cell tap then a digit tap each, with optional pencil, erase, and wait). Rounds (all `mode = "solo"`, `settings.level` as named, each with a `seed`): `solve-easy`, `solve-medium`, `solve-hard`, `solve-expert` (`steps(state)` taps the answer; `winners = {1}`; the last step `shows` the elapsed time and the best time, driven by `wait`), `notes-dots`, `notes-digits` (both toggle through the menu, `unfinished`), `erase-and-clue` (ERASE an own digit; ERASE a selected clue is `move = false` with `shows = "Clues cannot be changed"`), `undo-cell`, `undo-fill` (write, FILL NOTES, write, undo: the edit, then the whole fill, then the write before the fill), `ring-full` (a fill kept in the ring and more edits than the ring holds, so the snapshot is at its worst), `hint-wrong`, `hint-correct` (`shows` the rung name; the solve after it records no best time, `shows` the no-best line), `check`, `toggles` (SHOW REMAINING, SHADE PEERS, notes as digits; `shows` their state), `how-to-play` (`shows` the credit). A second-seed round is not possible (a round has one seed); the check above covers it.
