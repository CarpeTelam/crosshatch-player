# One device passes between players and hidden information stays hidden

## Description

Adds multi-seat play on one device: the roster and turn enforcement for N seats, per-seat `ui`, the runtime-owned hand-off for hidden games, game over with seat 0, Play again, and resume of pass matches. It also brings in the per-game title screen (`deferred-work.md` `## owner-e4-title-screen`): a launcher row opens it, and it offers Continue, New, and the mode, so the launcher lists one row per game.

## Outcome

Two players share one device and neither sees the other's private view; the CAP-6 success check and the pass part of CAP-5 are the signal.

## Requirements

This epic owns the pass-and-play part of CAP-5, CAP-6, the pass part of CAP-7, and the pass half of CAP-4's 3-tap check, plus the title screen that `## owner-e4-title-screen` triggers on this epic (written at inception, 2026-10-01). Lines without a CAP id cite their source.

- R1 (CAP-5; spine AD-11; game-api-seed §2): a pass match runs on `Roster{mode = pass, n, localSeats = every seat}`, fixed before `setup` and unchanged through Play again; `n` is within `max(2, seats.min)`..`min(seats.max, host maxSeats)`; `setup` gets `ctx = {seats = n, mode = "pass", api, settings}` (`settings` is the table of the player's chosen values, empty for a game with none); `Session` and the round driver serve any `localSeats` subset (every seat in pass, one in nearby) so epic-play-nearby reuses them; nothing in `GameCore`, `GameScript`, or `src/games` assumes n = 2, and host suites run n = 3 against a test host.
- R2 (CAP-5; spine AD-8, AD-9, AD-11): turns come from `status`: in pass, `draw` and `input` get `status.turn` (except R4 and R7), and with one local seat they get that seat; only a move from the turn seat reaches `apply`; a move returned while one awaits its result, or from a seat whose turn it is not, is discarded; a `turn` outside `1..n` is a script error (`LuaGame` already enforces it).
- R3 (spine AD-8; game-api-seed §2): each seat has its own `ui` table in pass and seat 0 a separate one at game over; the tables live for the match, kept across Play again as in solo, fresh after a resume, and never synced or saved (`LuaGame` already creates them per seat).
- R4 (CAP-6; spine AD-12, AD-21): in a `hidden = true` pass game, an accepted move that changes the turn seat enters `Result`: `draw` gets the mover's seat, a move `input` returns is discarded, and a runtime banner reads "Tap to pass to player N"; only a tap on the banner (or Confirm) shows the hand-off screen with a full refresh and no script drawing. The hand-off screen shows the game's `handoff.png`, else its `title.png`, else its icon at 128 px, in the title screen's 480 × 480 splash area, the text "Player N's turn" in the first menu row's place (none before seat 0), and an "I'm ready" button in the second's; only that button (or Confirm) draws the next seat. The banner and the button are plain tap targets with no time guard, and they overlap by the owner's choice, so a stray second tap on the banner's spot can pass the hand-off and one on "I'm ready" can become a move. No canvas frame of one seat is pushed after the hand-off until the next seat's own frame is ready. A script cannot draw during or suppress the hand-off.
- R5 (CAP-6; spine AD-12, AD-21): in a hidden pass game the hand-off screen (R4's, seat 0's without the "Player N's turn" line) also comes before the first draw of a new match, of each Play again, and of a resumed match; an open pass game never shows `Result` or the hand-off.
- R6 (CAP-6; spine AD-12, AD-20): in a hidden pass game the match's `onExit()` (sleep included) pushes a plain white screen (no icon, text, or image; the user's CrossPoint sleep screen then draws over it) with `displayBuffer(HALF_REFRESH)` under the `RenderLock` it already holds, without taking it again, only when a seat's frame may be on the panel, right after the VM's stop wait ends (joined or timed out) and before the first SD step (`flushResume()`) and the abandon's wait, so its refresh counts against the 1,500 ms window the SD steps share (as built here; spine AD-20's 2026-10-04 amendment moves the blank after the SD steps, e6pre-10); `game-canvas.md` records the order and the bound.
- R7 (CAP-5, CAP-7; spine AD-8, AD-21; game-api-seed §3): when a pass round ends, each seat 1..n's `input` gets `{kind = "over"}` exactly once with its own `ui`; from then on `draw` and `input` get seat 0; the end-of-round menu offers Play again (which calls `setup` again with the same roster) and Leave; entering Over deletes `resume.bin` and flushes `ch.store`.
- R8 (CAP-7; spine AD-17, AD-21): a pass match writes `resume.bin` with `mode` = pass and `n` after every committed snapshot, in any match state including `Result` and the hand-off, and in the forced exit, and deletes it on entering Over; `peek` reports a pass save, and a save whose mode or `n` the game or host cannot start is not offered and is kept; Continue rebuilds the roster from the save and, in a hidden game, shows the hand-off before the first draw; wake from sleep lands on Home.
- R9 (CAP-4; spine AD-22 as amended by entry 3): from Home a solo or pass game starts in at most 3 taps (Games, the game, a start on its title screen); the title screen is `GameModeActivity`, kept under its name so `goHome`'s mapping (ledger row 5) is unchanged; it offers Continue when a save exists (solo or pass, Valid or Unreadable as `peek` reports), New game, which starts the game's current mode (the mode last started, else `default_mode`), and Options, shown only when the host can start more than one of the game's modes or the game declares settings (a Mode row and one row per setting; spine AD-22 as amended 2026-10-02), and passes the mode, `n`, and the settings into the match; New over a save asks first, a fourth tap; the seat-choice rows are deferred (on a v1 host only `n` = 2 is possible, `deferred-work.md` `## e5-inception`).
- R10 (spine AD-15, AD-19; epic-install-and-launcher Decision on `HostCaps.pass`): `gameHostCaps()` sets `pass` true on the device and in the simulator; `Manifest::check` makes a manifest that declares `pass` with `seats.max` below 2 invalid, with the reason it gives nearby today (its text generalized), mirrored in `pack_game.py`, so a fresh install and the packer refuse it (installs stay strict and `pack_game.py` is unchanged, e5-r7), while a game already installed with such a claim keeps its other modes and the claim is unavailable, logged; this epic adds level-1 preview entries to `api-level-1.txt` (the manifest keys `default_mode` and `settings`, the reserved images `title.png` and `handoff.png`, and `ctx.settings`; `API_LEVEL_FROZEN` stays false).
- R11 (spine AD-23; game-api-seed §3): in pass a `timer` event goes to the turn seat; one that falls due in `Result` or the hand-off is delivered when the next seat is shown.
- R12 (SPEC Constraints; spine AD-2, AD-3, layer table, Operational envelope; epic-install-and-launcher retrospective AI-9): every new include edge is in the spine's layer table and `scripts/check_layers.py` in the same commit; upstream files change only in ledger row 2; this epic's x4pro flash and static-RAM delta (games on minus off), measured against the base measured before its first story, stays within 21,000 B and 32 B (measured +21,040 B at `55a8d9bf`, 40 B over, covered by the unallocated reserve and awaiting the owner's confirmation, as the Notes record; the share the owner raised from 11,152 B on 2026-10-02 and 2026-10-03, under a runtime flash gate of 270 KiB, 276,480 B, and a 1,024 B static-RAM limit).
- R13 (epic-install-and-launcher retrospective AI-4, AI-5; `docs/crosshatch/orchestrated-epics.md`): each test double an entry adds or extends names the device behaviour it stands in for, and a test pins that the two agree; host timing bounds come from the device ratio (about 95x) and are labelled estimates; a fixture whose outcome depends on device timing is calibrated on the device before the packet relies on it, or the packet marks it uncalibrated.
- R14 (risk high; epic-install-and-launcher retrospective AI-1, AI-11; `deferred-work.md` `## owner-e4-homes`): on an X4 Pro a person confirms the hand-off screen and its refresh and the plain white push before sleep, and records the cost of a `resume.bin` write, the time `peek` adds when the title screen opens, and that a Continue whose `.pkg` will not read ends in the error view with `resume.bin` untouched.
- R15 (`deferred-work.md`; epic-install-and-launcher retrospective AI-12): the open items this epic meets are fixed, documented, or deferred in the refactor sweep, each deferral with a reason the owner confirms; AI-12's installer refactor stays deferred unless an entry changes the installer.
- R16 (`deferred-work.md` `## owner-e4-title-screen`; epic-install-and-launcher A1, A12, A13, A14; retrospective rev-6, rev-11, agg-2): the launcher lists one row per game and no Continue rows; a row opens the game's title screen; after Leave the launcher selects the game's row; New over a save is an explicit choice on the title screen, so a Confirm under the install note can no longer start a New match over a save; a registry load that runs out of memory is reported, not shown as "No games found".
- R17 (`deferred-work.md` `## e3r-x`, `## 4.13` first item, `## owner-e4-homes` A15): while the next round starts after Play again, the pause menu shows one `tr()` line, "Starting the next round", under its headline.

## Done when

1. A hidden two-player fixture game and an open one each play a round in pass-and-play, started from Home in at most 3 taps, with turns enforced from `status` and out-of-turn moves impossible.
2. In a `hidden = true` game every change of turn seat, every new or resumed round, and every sleep shows the hand-off screen (a full refresh) before the next seat is drawn, and a sleep a plain white screen (a half refresh), and a script cannot suppress it, checked on an X4 Pro.
3. Play again, game over with seat 0, and one `over` event per local seat work.
4. Sleeping mid-match and choosing Continue restores a pass match, through the hand-off when the game is hidden.
5. Merged to `develop` with the five-env build, host suites, whole-tree format check, `pio check`, and the fork-only size and ledger jobs all green.

## Boundaries

`Roster` for pass with n within `seats` and the host maximum, `Session` and the round driver for N seats with no n = 2 assumption, per-seat `ui`, the Result and HandOff states, the `onExit()` blank push, pass `resume.bin`, the title screen in `GameModeActivity` (Continue, New, the mode), and the one-row launcher. Not the radio (epic-play-nearby). Not the seat-choice rows (deferred: a v1 host allows only 2), the title screen's instructions and options (they need new manifest keys), or an `api-level-1.txt` addition. Upstream: ledger row 2 only.

Handoffs: epic-play-nearby consumes the N-seat `Session` and `Roster` and the Over / Play again flow.
