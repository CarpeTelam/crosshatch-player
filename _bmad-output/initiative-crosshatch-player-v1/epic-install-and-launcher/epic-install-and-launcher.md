# Players install a game by dropping one file and start it in three taps

## Description

Adds the one installer and registry, the `.cpgame` packer, and the paged games launcher with Continue, remove, and a mode picker. Solo matches save and resume. The launcher replaces the minimal Games list from epic-script-runtime.

## Outcome

A player installs a game by putting one file on the SD card and starts it without help; the CAP-3 and CAP-4 success checks are the signal.

## Requirements

This epic owns CAP-3, the solo half of CAP-4, solo resume through Continue (CAP-7), and the launcher part of CAP-8 (written at inception, 2026-09-28). Lines without a CAP id cite their source.

- R1 (CAP-3; spine AD-16): opening Games installs every `/games/*.cpgame` with no reboot: `GamePackageInstaller` validates the package (AD-15), extracts it to `/.games-tmp/<id>/`, converts its images, removes any old `/.games/<id>/`, renames the new folder into place, writes `.pkg` last, and deletes the inbox file; a failed file is renamed `*.cpgame.bad` and its reason is shown once; a leftover `/.games-tmp/` is deleted when Games opens; all file access goes through `Storage` / `HalFile`.
- R2 (CAP-3; spine AD-15; game-api-seed §1, §6): a package is a flat zip, stored or deflate, no ZIP64, whose members are only `manifest.json`, `main.lua`, `[a-z0-9_]{1,32}.lua`, and `[a-z0-9_]{1,32}.png`; it holds at most 256 KB, 32 members, 128 KB per member uncompressed, and 128 KB of converted images counted as `GameCore::IMAGES_BYTES` counts them (62 + ceil(w / 32) * 4 * h per `.bmp`, `icon.bmp` excluded, at most `MAX_IMAGES`); the installer rejects a zip bomb (inflated size checked before extracting, output capped), path traversal and any other member name, a binary chunk, an over-limit member, image total, or package, a CRC mismatch over the streamed output, and an EOCD entry count that differs from the enumerated count, each with a host test; each limit is one named constant, mirrored in `pack_game.py`'s vectors with a case at the limit and one over, and listed in `docs/crosshatch/api-level-1.txt`.
- R3 (CAP-8; spine AD-16; epic-icon-library retrospective R7, AI-12): every package image goes through `PngToBmpConverter`, `icon.png` to a 64x64 `icon.bmp` and each other image to `<name>.bmp` at its own size, in the layout `GameCore::checkImageHeader` accepts; a failed conversion makes the package invalid; a `.bmp` member is not on the whitelist and makes the package invalid.
- R4 (spine AD-2, AD-16): `.pkg` holds `v1\n`, the 16 lowercase hex digits of the package hash, and `\n`; the hash is the first 8 bytes of a SHA-256 over the members sorted by name, each as `name \0 u32le(length) uncompressed-bytes`; one SHA-256 helper in `src/games` (mbedTLS on the device, OpenSSL in the simulator) computes it, and it and `scripts/pack_game.py` pass one shared test vector.
- R5 (CAP-3, CAP-4; spine AD-16, AD-17): the registry lists only `/.games/<id>/` folders with a valid `.pkg` whose name equals `manifest.id`, with no separate index; removing a game from the launcher deletes `/.games/<id>/`; reinstalling and removing both keep `/.games-data/<id>/`.
- R6 (spine AD-19, AD-25; Boundaries; `docs/crosshatch/fork-scripts.md`; epic-icon-library retrospective A3): `scripts/pack_game.py` is the only Python reader of `manifest.json` and keeps the release workflow's calling contract (`games/<id>/` in, `<id>.cpgame` out, the package hash on the last line, a nonzero exit on an invalid package); it refuses an `api` outside `API_MIN_LEVEL..API_LEVEL` read from `ApiLevel.h`, applies R2's rules, R3's image budget, and R9's icon check, and packs the same folder to the same bytes on one toolchain; the Lua-literal vector notation leaves `scripts/game_codec.py` in the commit where `pack_game.py` first imports the codec.
- R7 (CAP-4, CAP-8; spine AD-22, AD-24): the launcher, `GamesLauncherActivity`, replaces the minimal Games list: a paged `UiListActivity` of icon and name that pages past one screen; a row draws the package `icon.bmp`, or without one its manifest library icon through `drawGameIcon` by Phosphor name and weight; a game that `Manifest::check` finds `Unavailable`, such as one whose `api` exceeds the host's, shows as unavailable and does not start; no step needs text entry; runtime text is short `tr(STR_GAMES_*)`.
- R8 (CAP-4; spine AD-22): from Home a solo game starts in at most 3 taps (Games, the game, a mode); `GameModeActivity` lists the modes the host can start and is skipped when there is one; epic-pass-and-play adds the seat choice.
- R9 (CAP-8; spine AD-15, AD-24; epic-icon-library retrospective R6): the manifest `icon` is a library name in the library's grammar, `[a-z][a-z0-9]*(-[a-z0-9]+)*` of at most 32 characters, and an optional `icon_weight` is `regular` (the default) or `fill`; both are level-1 entries in `api-level-1.txt`; a name the library lacks makes the package invalid, checked outside `GameCore` at install and in `pack_game.py`.
- R10 (CAP-7; spine AD-17, AD-21): a solo match writes `/.games-data/<id>/resume.bin` (`{magic, fileVersion, codecVersion, pkgHash[8], mode, n, ver u16}` followed by the snapshot) through `GameSaveStore` after every committed snapshot and in the forced exit, and deletes it on entering Over; "Continue" is listed first in the launcher when a save exists; sleeping during a solo match and choosing Continue restores it; a save whose package hash or codec version differs is discarded; wake from sleep lands on Home.
- R11 (spine AD-20; epic-script-runtime retrospective AI-4, carried as epic-icon-library retrospective AI-13): the forced exit (sleep) bounds its time under `RenderLock`: the VM join and abandon waits count real elapsed time, and the bound is recorded in `docs/crosshatch/game-canvas.md`.
- R12 (epic-icon-library retrospective AI-1; epic-script-runtime retrospective AI-2): a `src/games` host harness (a Storage fake that lists folders, a PSRAM stub, a renderer double, and the match and list screens on the host) pins the device-side gaps in `deferred-work.md` `## 3.1`, `## 3.2`, `## 3.6`, `## 3.7`, `## 3.9`, `## 3.10`, `## e3r-1`, `## e3r-2`, and `## e3r-x`, plus the image-header read-error path of f27dcefd, and the launcher, mode picker, and installer screens are host-tested on it.
- R13 (SPEC Constraints; spine AD-2, AD-3, layer table, Operational envelope; epic-icon-library retrospective AI-9): every new include edge is in the spine's layer table and `scripts/check_layers.py` in the same commit; upstream files change only in ledger rows 2 and 5, each with its ledger text in the same commit; this epic's x4pro flash and static-RAM delta (games on minus off) is measured against the base measured before its first story and stays within its share in Notes.
- R14 (epic-icon-library retrospective AI-11; `deferred-work.md` `## e3r-1`, `## e3r-2`, `## e3r-x`; `cross-story-review-e3r.md` findings 12 and 13): the open hardening items are fixed, documented, or deferred in the refactor sweep, each deferral with a reason the owner confirms.
- R15 (Notes, risk high; epic-icon-library retrospective R1, AI-10; epic-script-runtime retrospective AI-3): on an X4 Pro a person confirms that saves survive reinstall and remove, and records the pending device runs.

## Done when

1. A valid `.cpgame` in `/games/` is installed and listed when the launcher opens, with no reboot; an invalid one is renamed `.bad` and its reason shown once; zip bombs, path traversal, binary chunks, over-limit members, and an EOCD count mismatch are rejected.
2. Reinstalling a game, and removing it from the launcher, both keep `/.games-data/<id>/`; `scripts/pack_game.py` and the device compute the same package hash on a shared vector.
3. From Home a solo game starts in at most 3 taps; the list pages past one screen; each row shows the package `icon.bmp` or its manifest library icon; a package whose `api` exceeds the host's shows as unavailable; no step needs text entry.
4. "Continue" is listed first when a save exists; sleeping during a solo match and choosing Continue restores it; a save from a changed package is discarded.
5. Merged to `develop` with the five-env build, host suites, whole-tree format check, `pio check`, and the fork-only size and ledger jobs all green.

## Boundaries

`GamePackageInstaller`, `GameRegistry`, `.pkg`, `Manifest::check`, `GamesLauncherActivity`, `GameModeActivity`, `resume.bin` in GameSaveStore, resume in the match, `scripts/pack_game.py`, and the SHA-256 helper. Consumes `lib/ZipFile`, `lib/miniz`, `lib/PngToBmpConverter`, `Storage`, and the web file manager unchanged. `scripts/pack_game.py` keeps the calling contract the fork release workflow (epic-platform-baseline entry 7) relies on: a `games/<id>/` directory in, `<id>.cpgame` out, the package hash printed, and a nonzero exit on an invalid package. Not a web Games page (deferred).

Handoffs: epic-pass-and-play extends the mode picker with the seat choice and resume with the hand-off.
