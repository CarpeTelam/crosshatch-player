## Intent

**Problem:** The 220 library bitmaps hold 70,400 B of flash, stored rotated in `GfxRenderer::drawIcon`'s layout, so `GameIconBlit::inkRuns` needs the whole bitmap to walk one drawn row.

**Approach:** `scripts/gen_game_icons.py` writes each bitmap PackBits-compressed in drawn orientation (one PackBits run set per drawn row); `inkRuns` decodes one row at a time into an 8-byte stack buffer. Games and screens draw exactly the pixels they draw today. `GAME_CONTROLLER_32` stays a raw array in `drawIcon`'s layout for Home's cover grid.

## Boundaries & Constraints

**Always:** No heap, no static buffer, no new failure path in the draw. Decoding is bounded and never reads past the bitmap's stored length. The per-frame pixel budget and the fill counts `GfxBindingsTest` checks are unchanged. Icon names, weights, `api-level-1.txt`, and `API_SURFACE_CRC` are unchanged. `drawGameIcon`/`drawGameIconAt`/`FrameReplay` signatures are unchanged.

**Never:** Edit `src/components/CoverGridHomeUi.cpp`, `.github/**`, `assets/game-icons/**`, or hand-edit the generated header. Use zlib or any decoder state beyond the row buffer.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Every library bitmap | packed bitmap | decodes to the same pixels as its raw bitmap | none |
| Malformed run | a row's runs overrun the row, a run or literal runs past the stored length, control 0x80, or the stored length runs out | rows before it draw; it and later rows draw nothing; no read past `2 + length` | none, silent |
| Clip | icon partly or wholly off the canvas | same runs as today; wholly off decodes nothing | none |

## Design Notes

**Layout.** A packed bitmap is a 2-byte little-endian length `N`, then `N` bytes of PackBits (control 0-127: copy the next control+1 bytes; 129-255: repeat the next byte 257-control times; 128 is never emitted and is malformed) that decode to the drawn rows, `pixels / 8` bytes each, MSB first, bit 0 = ink, bit `x` is drawn column `x`. A run may cross rows (Plan Change Log). The length prefix keeps `Icon` at pointers only (a separate length field would cost 4 B a bitmap, 880 B in all, in `ICONS`) and gives the decoder its bound. `PackedReader` gives one byte at a time; `inkRuns` asks for a row when the draw reaches it, so it decodes the rows above a clip (at most 63) and stops after the last visible one.

**Encoder.** `packbits` is the shortest encoding (dynamic programming, so the output is deterministic). Its cost is never larger for a later start, so a repeat is best as long as it can be, and a copy is best where `j + cost[j]` is least; the Python test checks the length against exhaustive search on 400+ inputs, including runs over 128.

**Guards kept in `inkRuns` and `inkAt`** (`git log -L`: b562ad3c added both, 131fe505 changed `inkRuns`): a null bitmap or non-positive `pixels` or `scale` draws nothing; the `int64_t` clip arithmetic (a `left` or `top` near the int32 limits cannot overflow); the wholly-off-canvas early return (131fe505: an off-canvas icon costs nothing, and it now decodes nothing either, since the return comes before the reader); runs clipped to the canvas columns. New: `pixels` not a multiple of 8, or over 64, draws nothing (the row buffer is 8 bytes). `inkAt` keeps its signature and its drawn-coordinate meaning, so `FrameReplayTest`, `ApiSurfaceTest`, and the other readers of it are unchanged; it now decodes the rows above `y`, so it is for tests, and says so.

**Decoder state.** The frozen Never line says no decoder state beyond the row buffer; the ticket's own rule is a row buffer of at most 8 B on the stack, no heap, no static buffer, no new failure path. `PackedReader` is about 24 B of locals in `inkRuns` (source pointer, read position, end, run counter, two flags, repeat value) beside the 8 B row, far under AGENTS.md's 256 B, and every one is a stack local.

**Malformed data.** Only a generator bug can produce it, and `static_assert(detail::allWellFormed())` in `GameIcons.h` rejects it at build time: every bitmap's runs are in bounds, none is control 128, and they decode to exactly the bitmap's bytes with none left over. It walks the runs without expanding them (a first version expanded them and used 800,000 to 1,048,576 of clang's 1,048,576-step limit; walking takes under 100,000), so it is a second parser of the reader's rule, and `GameIconBlitTest` checks the two agree on 20,000 random streams. The reader's own checks are the belt to that, and the test feeds it broken streams.

**Packed type.** The generated header defines `PackedBitmap`, one pointer with an explicit constructor, and `ICONS` holds those, so a raw array cannot be passed to the decoder by mistake; the two `size -A` sections were identical before and after the change to it, so it costs nothing.

**Raw controller.** `ICONS` holds a packed copy of game-controller regular 32 (named `_PB` like every packed array); the raw `GAME_CONTROLLER_32` is an extra array, so that bitmap is stored twice (128 B).

**Test reference (a file beyond `touches`).** The equivalence test needs the uncompressed bitmaps as independent ground truth. `test/game_script/GameIconsRaw.h` is that, beside the test (no CMake change: a quote include finds it), with `// clang-format off`. It is not named `*.generated.h` because `.gitignore` ignores that pattern and `.gitignore` is out of scope. A stale copy fails the C++ test (decode differs) or the Python test (differs from a fresh render). The Icons up to date job does not check it (`.github/**` is out of scope); deferred.
