# Digest: reality r1

Dimension D2: implementation reality and ecosystem health of the Claude Code plugin marketplace model. All findings were retrieved on 2026-10-04. Version dates come from the npm registry publish times for `@anthropic-ai/claude-code` (https://registry.npmjs.org/@anthropic-ai/claude-code), because the CHANGELOG carries no dates. Current version: 2.1.289, published 2026-10-03.

### Security
- claim: Anthropic's stated trust model: "A Claude Code plugin you install can execute arbitrary code on your machine with your user privileges." The install warning reads: "Make sure you trust a plugin before installing, updating, or using it. Anthropic does not control what MCP servers, files, or other software are included in plugins and cannot verify that they will work as intended or that they won't change." Hooks and MCP servers run outside the sandbox, and auto-update means "the files you reviewed can change on disk." | source: https://code.claude.com/docs/en/plugins/security | Anthropic | current | accessed 2026-10-04 | confidence high | class pattern
- claim: Plugin4Shell (disclosed 2026-09-17 by Air Security) was a zero-click RCE across Claude Code, Codex, Copilot and Gemini CLI. Attackers created a branch named exactly as the pinned 40-hex SHA; git prefers the ref, and clients never verified that HEAD equals the pinned SHA. Background auto-update made it zero-click. Claude Code patched it in 2.1.179 (June 2026) by checking that HEAD matches the pinned SHA after checkout. No in-the-wild exploitation was reported. The disclosing vendor sells a competing marketplace product. | source: https://www.air.security/blog-posts/plugin4shell ; corroborated by https://www.theregister.com/security/2026/09/17/ai-coding-agents-0-click-rce-flaw-could-hand-attackers-keys-to-the-kingdom/5297335 | Air Security / The Register | 2026-09-17 | accessed 2026-10-04 | confidence high | class failure
- claim: A proof-of-concept, not an incident: a benign-looking marketplace skill hijacks dependency installs, steering the agent to install a malicious httpx, from an unofficial public-repo marketplace. | source: https://prompt.security/blog/when-your-plugin-starts-picking-your-dependencies-marketplace-skills-and-dependency-hijack-in-claude-code | Prompt Security | 2026-01-05 | accessed 2026-10-04 | confidence high | class failure

### Retrospective / practitioner voices
- claim: Tuszynski (2026-04-20) argues the marketplace is "a governance layer, not a distribution channel". He recommends pinning to commit SHAs ("Tags move. Commits don't."), keeping the manifest-only marketplace repo separate from plugin source repos, and running stable and canary channels as two marketplaces pinned to different SHAs. He also recommends a seed directory (`CLAUDE_CODE_PLUGIN_SEED_DIR`) so CI and air-gapped hosts don't hit GitHub on every run and fail on rate limits or outages. This is a practitioner essay; it does not clearly document months of operating a marketplace. | source: https://www.mpt.solutions/your-claude-plugin-marketplace-needs-more-than-a-git-repo/ | The Cloud Codex | 2026-04-20 | accessed 2026-10-04 | confidence med | class pattern
- claim: Recommended monorepo practice: each plugin versions independently in its own plugin.json; CI regenerates marketplace.json from the plugin manifests on every push so catalog `version`/`source.ref` never drift; the version is bumped automatically from conventional commits. Comes from guides, not retrospectives. | source: WebSearch summary of https://systemprompt.io/guides/publish-plugin-claude-marketplace and https://dev.to/nagell/build-your-own-claude-code-marketplace-scaffold-structure-and-auto-updates-4n3f (the dev.to page's reported date of 2024-06-14 is implausible because it predates the feature) | various | 2026 | accessed 2026-10-04 | confidence low | class pattern

## Leads worth chasing
- Read the latest comments on #14061 and #17361 to see whether stale-cache reports continue on 2.1.28x. gh API access to anthropics/claude-code was blocked in this session; the MCP issue_read tool is the likely route.
- The official docs page on version resolution (`/docs/en/plugins/loading`, "When auto-update runs", "Cleanup of previous versions") gives the exact rule for the version-vs-commit cache key. This is the core design question for a game store on a device.
- The PromptArmor hook-hijack write-up and arXiv 2609.03884 cover update-time trust, which matters for any store that auto-updates.
- The archive `sha256` source type is the closest analogue to a firmware game package with a content hash, so it deserves a deeper read of marketplace-reference.
- Verify the "101 plugins in March 2026" baseline from a git history snapshot of claude-plugins-official to get a real growth curve.

## Looked for, not found
- No confirmed in-the-wild malicious plugin distributed through a Claude Code marketplace. Searches: "malicious Claude Code plugin marketplace supply chain", and "Claude Code malicious plugin found in the wild typosquat marketplace removed". Hits were proofs of concept (Prompt Security, PromptArmor), a vulnerability disclosure (Plugin4Shell, no exploitation reported), a typosquatted GitHub repo "Enxs969/skiller" hosting a Windows trojan (a fake repo, not a marketplace plugin, reported via claudeissues.com and unverified), and adjacent malvertising and fake-installer campaigns.
- No genuine retrospective, written months in, by someone who runs a public third-party marketplace and covers what they'd change. Both practitioner pieces found are prescriptive guides.
- No time series of the number of third-party marketplaces from a single consistent source. Aggregator counts are snapshots with different definitions.
- No dates in the claude-code CHANGELOG itself. All dates come from npm publish times.
