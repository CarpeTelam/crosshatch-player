### 1. Bundle format

- claim: An app is a plain folder `<app_id>/`. It holds `manifest.json`, `main.lua` (the entry script), an optional `icon.raw`, optional extra `.lua` modules and optional data or sprite files in subfolders, for example `sprites/coin_heads.raw` and `hours/compline.txt`. There is no single-file archive format on the device. A `.zip` exists only in the web portal, where the browser builds and unpacks it (see section 4). | source: apps/README.md:38-50@4dcb7fd; apps/catalog.json (dice, dailyoffice entries)@4dcb7fd | Mumfee/CrossSmudge | 2026-10-03 | accessed 2026-10-04 | confidence high | class feature
- claim: The manifest schema has exactly 6 string fields: `id`, `name`, `version`, `author`, `description`, `entry`. All 10 shipped manifests use exactly these 6 and nothing more. There are no permission, device, minimum-firmware, category or dependency fields. Example: `{"id":"2048","name":"2048","version":"1.0.0","author":"Mumfee","description":"...","entry":"main.lua"}`. | source: apps/README.md:73-78@4dcb7fd; apps/2048/manifest.json@4dcb7fd; key-frequency grep over apps/*/manifest.json | Mumfee/CrossSmudge | 2026-10-03 | accessed 2026-10-04 | confidence high | class feature
- claim: The firmware treats every manifest field as optional. Discovery accepts any folder that contains `manifest.json` or `main.lua`. If the manifest fails to parse, discovery logs `LOG_ERR` and still lists the app with the defaults. | source: src/activities/apps/lua/AppPackage.h:80-110@4dcb7fd | Mumfee/CrossSmudge | 2026-10-03 | accessed 2026-10-04 | confidence high | class feature

The value of `entry` is not checked for path traversal either. | source: apps/README.md:73@4dcb7fd vs src/activities/apps/lua/AppPackage.h:87,101,106@4dcb7fd | Mumfee/CrossSmudge | 2026-10-03 | accessed 2026-10-04 | confidence high | class feature
- claim: `icon.raw` is a 32x32, 1-bit, headerless bitmap of exactly 128 bytes. Each row is 4 bytes, MSB first. A 0 bit is black and a 1 bit is white. ### 2. Catalog

### 6. Device targeting

- claim: The manifest and the app catalog declare nothing about devices, screens or input. C3 versus S3 is handled by convention: every app must fit the C3's 75 KB Lua heap, which the simulator checks, and apps branch at runtime with `smudge.has_touch()` and `smudge.get_device()`. ## Looked for, not found

- Hashes or checksums for app files: grepped `sha|hash|verify` in AppStoreActivity.h and found none. catalog.json has no hash or size keys.
- Signatures or code signing anywhere in the app path: none found.
- A staging or temp directory plus rename for app installs: the only temp file is `catalog.tmp`. `rename` does not appear in AppStoreActivity.h.
- Resume within a file for app downloads: `resumePartial` is not set in AppStoreActivity.h.
- Semver comparison: only `!=` is used.
- Manifest fields for permissions, devices, input, minimum firmware or category: none in the README table, the 10 manifests or `AppPackage.h` parsing.
- Device-side zip extraction: none. Zips are handled only by JSZip in the browser.
- A size or quota limit on web app upload: none in `handleAppUploadData`.
- `/applications` endpoints in `docs/webserver-endpoints.md`: grep for "application" hits only JSZip and content types. The doc lags the code.
- An app-catalog generator: `generate_release_catalog.py` covers firmware only.
