# Import: freeink-sdk SSD1677 driver baseline (local, read 2026-10-16)

Source: `freeink-sdk/libs/display/FreeInkDisplay/src/driver/Ssd1677Driver.cpp`, `src/lut/Ssd1677Luts.h`, `freeink-sdk/docs/xteink-x4pro-support.md`, submodule checked out at freeink-sdk commit 111fdcc7 in this session (the superproject records 32a265fa; the pointer is not moved by this work). Primary source for the current baseline.

Claims:
- X4 Pro: ESP32-S3, 16 MB flash, 8 MB PSRAM, 800x480 B/W panel, GT911 touch. Panel controller varies by batch: SSD1677 on original units, UC8179 or UC8279 on UltraChip variants; same glass and pinout, driver chosen at boot (`xteink-x4pro-support.md` lines 3-14).
- Default X4/X4 Pro SSD1677 config drives the GDEQ0426T82-class panel with absolute CTRL2 sequences: FULL 0xF7 (~1800 ms), HALF 0xD7, PART 0xFC (~500 ms); the OTP waveform, no custom LUT (`Ssd1677Driver.cpp` lines 43-71).
- An opt-in `FREEINK_X4PRO_FAST_DU_SHORTCUT` sets `fastSeqOverride=0`, selecting the incremental CTRL2=0x1C differential-update path at ~77-85 ms/refresh; it skips per-refresh temperature load and power sequencing; artifacts (ghosting, blotching) reported over long sessions and across temperature on some panels (lines 105-156).
- Seeed Sticky (same SSD1677, same resolution) uses vendor sequences 0xF7 full / 0xFF partial because 0x1C runs the full OTP waveform (~1.7 s) on that panel (lines 73-102).
- The driver already writes a custom 112-byte LUT via command 0x32 for 4-level grayscale (`lut_grayscale`, `lut_factory_quality`), using the BW and RED RAM planes as the two bit planes; voltage tail bytes (VGH, VSH1, VSH2, VSL, VCOM) are per-module calibration (`Ssd1677Luts.h` lines 1-95).
- No revert LUT exists in the OEM firmware; grayscale exit is a RED resync or HALF clean (`Ssd1677Luts.h` lines 44-46).
- Measured on X4 Pro (prior run `technical-game-runtime-performance-2026-10-04`, owner serial log): fast 559 ms, half 1654-1720 ms, full 1489+ ms per refresh under the stock absolute sequences.
- The SSD1677 refresh path (`Ssd1677Driver.cpp` lines 274-360) has two branches: an absolute per-board CTRL2 sequence (0xF7/0xFC/0xD7 with border and temperature writes, self-cycling power), and an incremental bit-assembled path (0x1C for Fast, 0x34 Full, 0xD4 Half, 0xCC when a custom LUT is active). It supports asynchronous refresh (`displayStart` fires, `displayFinish` waits) and a `_customLutActive` state, so a custom LUT can already be loaded and activated with 0xCC without the OTP reload.
- The UC8179 batch driver (`Uc8179Driver.cpp` lines 43-100) uploads 42-byte LUTs to registers 0x20-0x24 in custom-LUT mode (PSR REG=1), carries the stock short 2-frame grayscale LUT set recovered from the factory firmware, and uses TSSET 0x5A as "the frame-rate lever that makes the partial shorter". So on both controller batches the SDK already knows how to upload a custom waveform.
- `freeink-sdk/docs/display-driver-references.md` maps the X4/X4 Pro SSD1677 to GxEPD2's GDEQ0426T82 driver and the UC8179 batch to GxEPD2's GDEY075T7 driver as reference implementations, and states that waveforms and forced-temperature values are panel-specific and must not be copied across panels.
