- (decision) Paradigm: hexagonal host. lib/GameCore is a pure C++ domain (sessions, seats, turns, snapshots, wire protocol, reliable link, manifest) with ports; adapters for Lua (lib/GameScript), ESP-NOW, storage, display live outside it. Script-facing contract is a reducer (Elm-style) with host-authoritative full-state replication. Prevents: rules code in two places, radio logic in scripts, non-host-testable core
- (decision) [ASSUMPTION] Build guard: fork flag FREEINK_CAP_GAMES=1 set in platformio.ini build_flags for x4pro and sticky only (FREEINK_CAP_USB_MSC precedent); every include of game code sits under it; new game libs must still compile for C3 because LDF chain mode ignores #if
- (decision) [ASSUMPTION] Upstream-touch cap: at most 10 upstream files changed, each hunk inside #if FREEINK_CAP_GAMES (or env-scoped ini lines / appended yaml keys), every touch listed in docs/crosshatch/upstream-touches.md; exceeding the cap needs a spine update
- (decision) [ASSUMPTION] VM threading: one VM at a time; a dedicated GameVM task (8 KB stack, core 1) owns the lua_State exclusively; loop task posts input events and render task consumes frames via bounded queues/buffers; loop task can cancel a running callback via an atomic flag checked in the count hook
- (decision) [ASSUMPTION] Drawing is a display list: ch.gfx calls append commands to a bounded frame buffer (PSRAM); frame is committed on draw() return with a refresh hint; render task replays the committed frame into GfxRenderer under RenderLock; Lua never touches GfxRenderer; 4 color levels, named font sizes, logical portrait coords from ctx.screen
- (decision) [ASSUMPTION] Game contract: main.lua returns a table {setup, status, apply, draw, input}; setup and apply run only on the authority; draw and input run on every device; ui table is per-device local and never synced; status(state) returns {turn=seat} or {over=true, winners={...}}
- (decision) [ASSUMPTION] State authority: canonical state is the serialized snapshot owned by GameCore Session; apply always starts from a fresh decode of the snapshot and its result is re-encoded; draw/input get a decoded copy whose mutations are discarded. Prevents host/guest divergence and hidden state mutation from views
- (decision) [ASSUMPTION] Snapshot codec: one C codec for sync and save; values nil/bool/integer/float/string/tables with string or integer keys, acyclic, no metatables/functions/userdata, depth <= 16; snapshot <= 1400 B and move <= 256 B, enforced identically in every mode so one script works in both modes
- (decision) [ASSUMPTION] Seats & modes: seats are 1..N (manifest seats.min/max; v1 N=2); modes solo, pass, nearby; the authority is the local device in solo/pass and the host in nearby; host is seat 1; runtime accepts moves only from status().turn; turns strictly sequential
- (decision) Hand-off screen is runtime-owned: in pass mode when manifest hidden=true and the turn seat changes, runtime shows a blank full-refresh hand-off prompt before drawing the next seat; scripts cannot draw during or suppress it (from brief)
- (decision) [ASSUMPTION] Wire protocol: little-endian envelope {magic 'XH', proto u8, type u8, session u32, seq u16, ack u16, payload}; types ADVERT, JOIN, ACCEPT, MOVE, STATE, ACK, ABORT, PING; host resends unacked every 400 ms, peer dropped after 10 s silence; lobby matches only on equal proto, api and package hash; ESP-NOW v2 on fixed channel 1, broadcast adverts, unencrypted
- (decision) [ASSUMPTION] Radio ownership: one NearbySession object owns Wi-Fi+ESP-NOW; created by the lobby, moved into the match, torn down with it; never coexists with the web server or any other Wi-Fi activity; match sets preventAutoSleep; teardown never takes RenderLock
- (decision) [ASSUMPTION] Package: .cpgame = zip (stored or deflate, read via lib/ZipFile) holding manifest.json, main.lua, optional *.lua modules loaded by a package-jailed require, optional icon.png; manifest id matches ^[a-z0-9][a-z0-9-]{0,31}$, declares name, version, api, seats, modes, hidden
- (decision) [ASSUMPTION] Install & registry: one GamePackageInstaller used by the web Games page (/api/games, /api/games/upload, /api/games/delete, modeled on fonts) and the launcher's SD inbox /games/*.cpgame; validates then extracts to /.games/<id>/ via a temp dir and rename; records SHA-256 (first 8 bytes) of the package as its hash; registry is a directory scan of /.games/*/manifest.json; game data lives in /.games-data/<id>/ so reinstall keeps saves
- (decision) [ASSUMPTION] Persistence: runtime auto-saves the session snapshot+seats+mode for solo/pass resume in /.games-data/<id>/; scripts get ch.store (one table, same codec, <= 4 KB) for high scores; no file API; save dropped if package hash changes
- (decision) [ASSUMPTION] Errors: any script error, budget or memory exhaustion ends the session: VM destroyed, peer sent ABORT, LOG_ERR, runtime error screen with game name and Lua message; no auto-retry
- (decision) [ASSUMPTION] API surface: one reserved global table ch (ch.api, ch.gfx, ch.store, ch.time, ch.log, ch.screen); manifest api integer; additive-only within an api level; launcher disables packages whose api exceeds the host's
- (decision) First-party games are sources under games/<id>/ packed to .cpgame by scripts/pack_game.py and installed like any third-party game (dogfoods the install path); not embedded in firmware
